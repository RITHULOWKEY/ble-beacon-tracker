How the simulation works

1. Simulating RSSI (path-loss model)

Signal strength falls with distance. For every beacon the simulator computes

RSSI = P0 - 10 * n * log10(d) + X

P0 is the power at 1 m (transmission power slider), n the path-loss exponent, d the distance in metres, and X a random Gaussian noise term with standard deviation sigma (noise slider). Values are rounded to whole dBm, like a phone reports them.

2. RSSI to distance

The receiver does not know the true distance. It inverts the model:

d = 10 ^ ((P0 - RSSI) / (10 * n))

Readings are first smoothed with an exponential moving average, filtered = alpha * new + (1 - alpha) * old, because single BLE readings jump a lot. The beacons hang 2.3 m high and the phone is at 1.2 m, so the horizontal distance is sqrt(d^2 - 1.1^2).

3. Position estimate (trilateration)

Each beacon i gives a circle (x - xi)^2 + (z - zi)^2 = di^2 around itself. The receiver should be where the three circles meet. Subtracting the last circle equation from the other two removes the squared terms and leaves two linear equations in x and z, which are solved by least squares.

Because every distance has an error, the circles do not meet in exactly one point. That gap is the position error you see on the dashboard. The default setting starts from this linear solution and then applies a few Gauss-Newton steps that minimise the weighted range error (far beacons, which are noisier, count less). You can also switch to the plain linear solution or to a weighted centroid (average of the beacon positions, nearer beacons count more) and compare the errors.

4. Nearest beacon, handoff and room

The nearest beacon is the one with the strongest filtered RSSI. When it changes (and stays changed for three scans), the 3D view plays a handoff pulse. The pink dots near the estimate marker are the unfiltered per-scan estimates, so their spread shows the measurement noise. The estimated room is the room rectangle that contains the estimated (x, z) point.

5. Simulation versus real BLE hardware

Real RSSI is also affected by multipath reflections, body shadowing, walls, phone orientation, antenna differences and 2.4 GHz interference. This simulation uses one noise model and ignores walls for the signal, so it shows the principle but not the exact accuracy of a real deployment. Validating the model needs real measurements, for example with ESP32 or nRF52 beacons and a phone scanner app.
